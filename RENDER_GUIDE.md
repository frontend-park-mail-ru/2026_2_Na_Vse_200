# `render.js`: подробное руководство для новичка

Это руководство объясняет тот самый текст, который ты вставил: текущий `render.js` проекта. Сначала разберём общую идею, синтаксис и применение в приложении; потом пройдём код по порядку. В конце находится точная копия исходника с номерами строк, чтобы ты мог быстро найти объясняемый участок.

## 1. Что делает этот файл

Браузер умеет показывать настоящие HTML-элементы: кнопки, поля ввода, заголовки. А JSX вроде `<button>Играть</button>` в этом проекте превращается сначала в обычное JavaScript-описание элемента. Это описание называют виртуальным элементом: оно говорит, что должно быть на странице, но само ещё не является кнопкой браузера.

`render.js` берёт такие описания и создаёт или обновляет настоящий DOM — дерево объектов страницы, которым управляет браузер. Он сравнивает новое описание со старым и меняет только то, что поменялось. Если поменялся текст кнопки, старается поменять текст в прежнем DOM-узле, а не пересоздать всю страницу.

Главные части файла:

- `render` начинает отрисовку приложения;
- `useState` хранит состояние компонента и запускает обновление;
- `reconcile` сравнивает старое и новое дерево;
- `getChildPath` связывает дочерний элемент с его адресом, используя `key` или индекс;
- `clearPath` очищает данные удалённой ветки;
- `updateProps` задаёт DOM-элементам свойства, атрибуты, стили и обработчики событий.

Это небольшой самописный механизм, вдохновлённый React. Он не является библиотекой React и реализует только нужные проекту возможности.

## 2. Как обновление проходит через файл

```text
Пользователь нажимает кнопку
    ↓
браузер вызывает обработчик onClick
    ↓
обработчик вызывает setState
    ↓
useState сохраняет новое значение и вызывает render
    ↓
render вызывает reconcile с новым виртуальным деревом
    ↓
reconcile повторно вызывает компоненты и сравнивает их результат
    ↓
updateProps / reconcile обновляют настоящие DOM-узлы
```

Компонент не меняет DOM сам. Он возвращает описание интерфейса; общий движок применяет это описание к DOM.

## 3. Переменные в начале файла

| Переменная              | Для чего нужна                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| `SVG_NAMESPACE`         | Строка-адрес, по которому браузер распознаёт SVG-элементы.                                                   |
| `rootElement`           | Последнее верхнее виртуальное дерево приложения. Его использует `setState`, чтобы снова запустить отрисовку. |
| `rootContainer`         | Настоящий HTML-элемент, внутрь которого монтируется приложение, обычно элемент `#root`.                      |
| `hooksByPath`           | Карта состояний компонентов. По пути компонента хранит массив значений его `useState`.                       |
| `componentOutputByPath` | Карта виртуальных деревьев, которые компоненты вернули при прошлой отрисовке.                                |
| `domByPath`             | Карта настоящих DOM-узлов по их путям в дереве.                                                              |
| `currentPath`           | Путь компонента, который сейчас выполняется. По нему `useState` находит своё состояние.                      |
| `currentHookIndex`      | Позиция следующего `useState` в текущем компоненте. Счёт начинается с нуля.                                  |

Например, путь `'0.index:2.render'` можно представить как адрес: корень `0`, третий ребёнок `index:2`, затем результат выполнения компонента `render`.

## 4. Синтаксис, который встречается в коде

### `const` и `let`

`const` создаёт имя, которому нельзя потом присвоить другое значение. `let` разрешает такое переназначение.

```js
const previousRootElement = rootElement
let rootElement = null
```

В первой строке сохраняется ссылка на старое дерево. Во второй заводится переменная, в которую позже `render` положит новое дерево. Если `const` содержит массив или карту, сам массив/карту менять можно — запрещено только присвоить переменной совсем другое значение.

### `Map`

`new Map()` создаёт таблицу «ключ → значение». Здесь ключом служит строковый путь компонента или элемента.

```js
hooksByPath.set(path, hooks) // запомнить массив состояний
hooksByPath.get(path) // найти его
hooksByPath.delete(path) // удалить запись
```

Переменные внутри компонента исчезают после завершения его функции. Карты живут между вызовами `render`, поэтому сохраняют состояния, DOM-ссылки и старые описания.

### `??` и `?.`

`a ?? b` подставляет `b`, только если `a` равно `null` или `undefined`. Значения `false`, `0` и `''` он оставляет как есть.

```js
hooksByPath.get(path) ?? []
```

Это значит: «получи сохранённый массив; если записи нет, используй пустой массив».

`value?.property` — безопасное чтение свойства. Если `value` равен `null` или `undefined`, выражение даст `undefined`, вместо того чтобы выбросить ошибку.

### Логика и `if`

```js
if (!dom || (!sameType && !(isText && previousIsText))) {
```

Прочитай это как: «создай узел, если прежнего DOM нет ИЛИ (тип элемента изменился И это не случай, когда старый и новый узлы оба являются текстом)».

- `!x` — отрицание: «не x»;
- `a && b` — нужны оба условия;
- `a || b` — достаточно одного условия;
- `===` — строгое равенство, `!==` — строгое неравенство.

Скобки задают группы условий и помогают понять их порядок.

### `условие ? да : нет`

Тернарный оператор — короткая форма выбора:

```js
const word = isReady ? 'Готово' : 'Загрузка'
```

Если `isReady` истинно, результат `'Готово'`, иначе `'Загрузка'`. В `render.js` таким способом выбирают, какой DOM-узел создать: текстовый, SVG или HTML.

### Стрелочные функции `=>`

```js
const setState = nextValue => { ... }
```

Это объявление функции с параметром `nextValue`. Такая функция вызывается позже. Здесь `setState` вызывается компонентом в ответ на действие пользователя.

```js
nextDomChildren.forEach((childDom, index) => { ... })
```

`forEach` запускает функцию для каждого элемента массива. `childDom` — текущий элемент, `index` — его позиция.

### Массивы, `Set` и перебор

- `items[index]` получает элемент по номеру, с нуля.
- `array.push(value)` добавляет значение в конец массива.
- `findIndex(fn)` ищет первый элемент, для которого `fn` вернула `true`; если такого нет — выдаёт `-1`.
- `new Set()` создаёт набор без повторов; `.add(x)` добавляет, `.has(x)` проверяет наличие.
- `Object.keys(object)` возвращает имена свойств объекта.
- `Array.from(dom.childNodes)` делает копию списка дочерних узлов. Копия нужна, потому что во время прохода DOM изменяется.

### Шаблонная строка и `...`

Обратные кавычки позволяют встраивать значения:

```js
;`${path}.render`
```

Если `path` — `'0.index:1'`, получится `'0.index:1.render'`.

`...` в `new Set([...oldNames, ...newNames])` раскладывает элементы массивов внутрь нового массива. Так объединяются имена прежних и новых свойств. А `encodeURIComponent(String(key))` сначала превращает ключ в текст, затем кодирует специальные символы для безопасного пути.

### Комментарии JSDoc

Блок `/** ... */` — комментарий для человека и редактора, он не выполняется программой. Например, `@param {Node} dom` говорит, что аргумент `dom` должен быть DOM-узлом. `@returns {Node|null}` означает, что результат — DOM-узел или `null`. Фигурные скобки в JSDoc указывают тип значения.

## 6. Как `render.js` вызывается в этом проекте

1. [src/main.jsx](src/main.jsx) берёт корневой DOM-контейнер и запускает `mountApp`.
2. [src/app/App.jsx](src/app/App.jsx) создаёт верхнее JSX-дерево приложения и вызывает `render(tree, container)`.
3. Vite преобразует JSX в вызовы [createElement.js](createElement.js). Они создают виртуальные объекты, а не DOM.
4. `render` вызывает `reconcile` для пути `0`.
5. Когда `reconcile` встречает функцию-компонент вроде `AppLayout`, `HomePage`, `Sidebar` или `Player`, оно вызывает эту функцию с props.
6. Когда встречается обычный HTML-тег, движок создаёт DOM-узел и заполняет его через `updateProps`.
7. Когда компонент вызывает `useState`, значение сохраняется под путём компонента и номером хука.

Получается цепочка: `main.jsx → App.jsx → render → reconcile → компоненты → DOM`. Обратная цепочка при клике: `DOM-событие → обработчик компонента → setState → render → reconcile → изменённый DOM`.

## 7. Пример из проекта: кнопка воспроизведения

В [Player.jsx](src/components/player/Player.jsx) компонент получает состояние через `useState(false)` и передаёт кнопке обработчик нажатия.

1. При первом проходе `reconcile` видит компонент `Player`, сохраняет его путь и сбрасывает счётчик хуков.
2. `Player` вызывает `useState(false)`. Движок записывает `false` в первую ячейку массива этого компонента.
3. JSX-кнопка создаётся как виртуальное описание. `updateProps` устанавливает её `onClick` через `addEventListener`.
4. Пользователь нажимает кнопку. Браузер вызывает сохранённый обработчик, а он вызывает функцию `setIsPlaying`.
5. Функция setter находит состояние по запомненным пути и индексу, записывает обратное значение и запускает `render`.
6. `reconcile` вызывает `Player` снова по тому же пути. `useState` получает новое сохранённое значение.
7. Если изменился лишь значок, сравнение дерева оставляет прежние элементы и обновляет необходимое свойство/узел.

`useState` не меняет страницу напрямую. Он меняет JavaScript-состояние и просит движок пересчитать описание страницы.

## 8. Пример из проекта: список треков и `key`

`HomePage.jsx` строит элементы списка из массива. Для каждого трека JSX указывает `key={track.id}`. Эта информация хранится рядом с виртуальным элементом, но не становится HTML-атрибутом.

Допустим, список сначала `[A, B, C]`, а после обновления `[C, A, B]`. `getChildPath` строит пути на основе ключей. `reconcile` узнаёт те же самые треки по прежним путям, а `insertBefore` перемещает соответствующие DOM-узлы в новый порядок. Поэтому внутреннее состояние карточки остаётся при своём треке. Если ключа нет, путь зависит от позиции (`index:0`, `index:1`...), и при изменении порядка элементы сопоставляются хуже.

Ключи у соседей должны быть уникальными и стабильными: для одного трека использовать его id, а не случайное число, которое меняется на каждом рендере.

## 9. Как объяснить любой фрагмент кода самому себе

Для каждой функции задай пять вопросов:

1. Что она получает? Найди параметры в скобках после имени.
2. Что хранится в переменных? Посмотри, откуда пришло каждое значение.
3. Какие проверки она делает? Проговори `if`, `&&`, `||`, `??` словами.
4. Что меняется? Это может быть карта, массив, DOM или состояние.
5. Что функция возвращает или запускает дальше?

Для выражения, которое пока непонятно, сначала определи его внешнюю форму. Например, у `nextValue === null || nextValue === undefined || nextValue === false` есть три простые проверки, соединённые через «ИЛИ». Затем объясни каждую часть и почему она ведёт в этот блок.

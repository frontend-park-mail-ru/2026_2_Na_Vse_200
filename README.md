# 2026_2_Na_Vse_200
Frontend репозиторий команды На все 200 с проектом Spotify/Яндекс Музыка

## Локальный запуск

Нужны Node.js 22.12+ (либо 24+) и npm. Из корня репозитория:

```sh
npm ci
npm start
```

Откройте адрес, напечатанный Vite (обычно http://127.0.0.1:5173).
В Windows PowerShell при блокировке `npm.ps1` используйте `npm.cmd` вместо `npm`.
Backend для запуска каркаса не требуется.

```sh
npm run lint
npm test
npm run build
npm run preview
```

`npm run test:routes` собирает проект и автоматически проверяет прямые URL
на dev-сервере и preview. Проверка запускает временные локальные серверы и закрывает их.

Сборка находится в `dist/`. Preview проверяет готовую сборку локально (обычно порт 4173).
Vite dev и preview поддерживают SPA fallback: `/login`, `/signup` и неизвестные
адреса возвращают приложение, после чего страницу выбирает клиентский роутер.
На production-сервере также нужно настроить возврат `index.html` для маршрутов SPA,
не подменяя им API и отсутствующие статические ресурсы. Развёртывание относится к MUSIC-26.

## Каркас MUSIC-20

Используются ES-модули, JavaScript, JSX-шаблоны и собственный движок в корне проекта,
перенесённый вместе с `VanillaRouter` из MUSIC-22. Сторонних библиотек в runtime нет.
Vite и ESLint — инструменты разработки. React-плагины не используются;
локальное правило ESLint учитывает JSX-компоненты и собственную фабрику `createElement`,
сохраняя проверку неиспользуемых переменных.
TypeScript и Babel не входят в текущий объём РК1.

| URL | Страница |
| --- | --- |
| `/` | Заготовка главной; каталог подключается в MUSIC-22 |
| `/signup` | Заготовка регистрации; форма реализуется в MUSIC-9 |
| `/login` | Заготовка входа; форма реализуется в MUSIC-21 |
| Любой неизвестный путь | 404 со ссылкой на главную |

`src/main.jsx` запускает приложение; `src/app/router.js` содержит единственную таблицу
маршрутов; `src/app/App.jsx` связывает роутер со страницами; `src/components/layout/`
содержит общую навигацию; страницы находятся в `src/pages/`.
Новый JSX-компонент импортирует `createElement` из корневого `index.js`.
Движок состоит из трёх файлов:

- `createElement.js` — создание виртуальных элементов из JSX-шаблонов.
- `render.js` — согласование виртуального дерева с DOM и функция состояния `useState`.
- `index.js` — общий экспорт `createElement`, `render` и `useState`.

JSX преобразуется Vite в вызовы собственного `createElement`. Движок не зависит
от страниц, роутера или компонентов приложения.

Внутренние ссылки используют `href` и `data-link`. Роутер сохраняет стандартное поведение
Ctrl/Cmd-клика, внешних ссылок, `target` и `download`.

При интеграции MUSIC-22 сохранить этот роутер и маршруты входа/регистрации, заменить
заготовку `HomePage` каталогом и согласовать общий `AppLayout`. Второй роутер не нужен.
В старом `App.jsx` MUSIC-22 также необходимо исправить регистр `mainpage` на `mainPage`.

## API и cookies

Скопируйте `.env.example` в `.env.local` и задайте `VITE_API_ORIGIN` — origin backend,
например `http://localhost:8080`, без `/api/v1`. После изменения перезапустите dev-сервер;
для production пересоберите проект. Значение публичное, секреты туда помещать нельзя.

`src/config.js` экспортирует `API_ORIGIN`, `API_URL` (origin + `/api/v1`)
и `API_REQUEST_OPTIONS` с `credentials: 'include'` для будущих запросов с cookies.
Проверка здоровья находится по `${API_ORIGIN}/health`, вне `/api/v1`.
Каркас сам запросов не отправляет. Восстановление сессии и выход относятся к MUSIC-11.

Для требуемого кросс-доменного взаимодействия frontend обращается непосредственно
к backend, без dev-прокси. Backend должен разрешать точный origin открытого frontend
через `Access-Control-Allow-Origin` и credentials через `Access-Control-Allow-Credentials: true`.
`localhost` и `127.0.0.1` — разные хосты: согласуйте адреса и настройки cookies с backend.
Для cross-site cookies на стенде потребуются HTTPS и соответствующие флаги cookie.
Окончательная проверка CORS, cookie-сессии и интеграции выполняется с настоящим backend.

## Проверка MUSIC-20

1. Запустить приложение по инструкции на чистой установке зависимостей.
2. Открыть `/`, `/signup`, `/login` напрямую и обновить каждую страницу.
3. Перейти между страницами через навигацию: документ не должен перезагружаться.
4. Проверить кнопки браузера «Назад» и «Вперёд», активную ссылку и заголовок вкладки.
5. Открыть `/unknown/nested`: должен появиться экран 404, ссылка возвращает на главную.
6. Проверить навигацию с клавиатуры и на узком экране, Ctrl/Cmd-клик открывает новую вкладку.
7. Повторить открытие URL на production-сборке через `npm run preview`.

Это каркас, а не завершение всех требований РК1: формы, их валидация, авторизация,
данные каталога и деплой выполняются отдельными задачами. Финальная приёмка по Jira
также зависит от MUSIC-31 (сверка требований) и MUSIC-7 (согласованные макеты).

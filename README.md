# 2026_2_Na_Vse_200

Frontend репозиторий команды На все 200 с проектом Spotify/Яндекс Музыка

## Локальный запуск

Нужны Node.js 24.11+ и npm. Из корня репозитория:

```sh
npm ci
npm start
```

Откройте адрес, напечатанный Vite (обычно http://127.0.0.1:5173).
В Windows PowerShell при блокировке `npm.ps1` используйте `npm.cmd` вместо `npm`.
Для входа, регистрации и проверки сессии нужен бэкенд на `http://127.0.0.1:8080`.
Vite перенаправляет на него запросы `/api` и `/health`.

```sh
npm run lint
npm run build
npm run preview
```

Сборка находится в `dist/`; её нужно передать серверу, раздающему фронтенд.
Preview проверяет готовую сборку локально (обычно порт 4173).

## Настройка API

Для локального запуска через прокси оставьте `VITE_API_ORIGIN` пустым.
Если API работает на отдельном домене, скопируйте `.env.example` в `.env.local`
и задайте `VITE_API_ORIGIN` — адрес бэкенда без `/api/v1`.
После изменения перезапустите dev-сервер или пересоберите проект.

Авторизация использует серверную cookie-сессию. Клиент передаёт запросы с
`credentials: 'include'`, восстанавливает пользователя через `/api/v1/auth/me`
при запуске и завершает сессию через `/api/v1/auth/logout`.

## Локальный пакет my-react

Собственный JSX-движок вынесен в TypeScript-пакет `packages/my-react` с именем
`@navse200/my-react`. Он подключён в `dependencies` приложения через npm workspaces;
`npm install` / `npm ci` связывают его с приложением без публикации в npm.

```ts
import { createElement, render, useState } from '@navse200/my-react'
```

`npm run build:packages` компилирует пакет в ESM JavaScript и `.d.ts` в его `dist/`.
Эта сборка автоматически выполняется перед запуском dev-сервера, проверкой типов,
сборкой сайта. После изменения исходников пакета при уже запущенном
dev-сервере повторите `npm run build:packages`.

`npm pack --workspace @navse200/my-react` создаёт отдельный устанавливаемый архив.
Команда `prepack` сначала собирает пакет. Архив можно установить в другом проекте
через `npm install ./navse200-my-react-1.0.0.tgz`; исходники приложения для этого
не нужны. В Git хранятся исходники пакета, а его `dist/` генерируется при сборке.
Подробнее — [README пакета](packages/my-react/README.md).

## Оффлайн-режим

Приложение, профиль, страница артиста, оффлайн-модули и Service Worker написаны
на TypeScript. В dev объединены общий TS-код, профиль и изменения MUSIC-51;
используется одна копия движка `@navse200/my-react`, включая поддержку ref для модальных окон.

В production-сборке `vite-plugin-pwa` компилирует `src/sw.ts` в `dist/sw.js`
и добавляет список HTML/JS/CSS и локальных ресурсов для предварительного кеша.
Регистрация находится в `src/shared/offline/register.ts`. В dev-сервере worker
не регистрируется, поэтому проверять оффлайн нужно через build + preview.
На localhost/127.0.0.1 HTTPS не требуется; на публичном адресе нужен доверенный HTTPS.
Сервер должен отдавать `/sw.js` как JavaScript, а маршруты SPA — как `index.html`.
Новая версия worker ждёт закрытия вкладок старой версии, без принудительной перезагрузки плеера.

Данные главной и ранее открытых исполнителей сохраняются в IndexedDB браузера.
Исполнитель загружается отдельным запросом `/api/v1/artists/{id}`; отдельно
сохраняются только действительно открытые исполнители. Неоткрытый экран без сети
покажет сообщение о недоступности. Загруженные обложки вне `/api/` кешируются
отдельно (до 100 изображений на 7 дней).

Кеш данных разделён по ID пользователя. Для восстановления отображения хранятся
только ID, имя, email и URL аватара; пароли, cookies и токены не сохраняются.
Сетевая ошибка `/auth/me` позволяет открыть сохранённые экраны в режиме просмотра.
Ответ `401` очищает локальную личность и её кеш; успешный выход и смена аккаунта
также удаляют данные предыдущего пользователя. Ответы HTTP 4xx/5xx и неверный
формат данных не подменяются старыми данными. Если IndexedDB недоступна или
переполнена, онлайн-загрузка продолжает работать без сохранения.

Профиль доступен по `/profile`: есть просмотр, редактирование имени и выбор аватара.
В оффлайне профиль доступен для просмотра сохранённых данных, а редактирование отключено.
Вход, регистрация и выход требуют сети. После возвращения подключения открытый
экран повторно проверяет сессию и обновляет каталог; есть и ручная проверка связи.

Аудиофайлы и API-ответы Service Worker не кеширует. Плеер использует один нативный
аудиоэлемент на монтирование. Адрес строится из ID трека:
`GET /api/v1/tracks/{id}/audio` на текущем origin API. Ссылки на аудио в данных
каталога не нужны. Бэкенд должен найти файл по записи БД, прочитать его из папки
медиа и отдать с поддержкой HTTP Range для перемотки. Этот обработчик добавлен
в локальный Go-бэкенд. При обрыве сети источник не сбрасывается: трек играет,
пока хватает буфера браузера. Затем отображается сообщение о подключении;
перемотка без сети ограничена доступными диапазонами `seekable`. Перезагрузка
страницы, переключение трека и повтор старых фрагментов без интернета не гарантируются.
Кнопки скачивания и отдельного сохранения аудио нет.

Проверка вручную:

1. Выполнить `npm run build`, затем `npm run preview`.
2. Открыть сайт онлайн, войти и открыть главную и исполнителя.
3. В DevTools → Application → Service Workers дождаться активации worker.
4. В Network включить Offline и перезагрузить страницу: сохранённый экран должен открыться.
5. Проверить переходы по сохранённым экранам и сообщение для неоткрытого исполнителя.
6. Отдельно отключить сеть во время проигрывания трека, доступного через `/api/v1/tracks/{id}/audio`: буфер не сбрасывается.

Автоматические проверки:

```sh
npm run typecheck
npm run lint
```

### Локальная работа с Go-бэкендом

В каталоге `WEB/backend/2026_2_Na_Vse_200` запустите `docker compose up --build -d`.
В каталоге фронтенда запустите `npm start` и откройте адрес Vite (обычно http://127.0.0.1:5173).
Запросы `/api/v1/*` и `/health` проксируются на http://127.0.0.1:8080;
`VITE_API_ORIGIN` для этого режима оставьте пустым. Cookie сессии передаются автоматически.
Главная открывается по `/`, исполнитель — по `/artists/<UUID из БД>`.
Страница исполнителя получает данные из `GET /api/v1/artists/{id}` независимо от главной
и сохраняет их для оффлайна. При 404 показывается «Исполнитель не найден».
Пустая БД означает пустой каталог: демонстрационные треки не подставляются.
Аудиофайлы хранятся в `media/` бэкенда (для нативного запуска можно задать `MEDIA_ROOT`).
В БД хранится относительный `storage_key`, например `audio/demo/<id>.wav`.
Плеер запрашивает `GET /api/v1/tracks/{id}/audio`; сервер отдаёт файл с поддержкой Range.
В Docker папка `./media` подключена к контейнеру сервера, аватары сохраняются в ней же.

Профиль сохраняется двумя запросами: `PUT /api/v1/users/{id}` с JSON
`email` и `display_name`, затем, если выбрано фото, `POST /api/v1/users/{id}/avatar`
с multipart-полем `avatar`. Допустимы JPG, PNG и WebP до 2 МиБ.
При ошибке загрузки фото уже сохранённое имя отображается, а форма сообщает об ошибке.

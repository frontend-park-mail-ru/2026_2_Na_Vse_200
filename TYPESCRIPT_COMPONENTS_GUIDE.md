# TypeScript, компоненты и рендеринг в этом проекте

Это учебник по текущему исходному коду. Открой рядом `src/components/ui/FormField.tsx`, затем `src/components/player/Player.tsx`, затем `createElement.ts` и `render.ts`.

## 1. Что запускается

В проекте нет пакетов `react` и `react-dom`. Здесь собственный учебный движок MyReact: `createElement`, `render`, `useState`. JSX похож на React, но поведение определяется нашим кодом.

Три разных уровня:

1. **TypeScript** проверяет исходники: правильные ли аргументы функции, существует ли свойство, подходит ли тип значения.
2. **JSX** позволяет удобно записать дерево интерфейса. Vite преобразует его в вызовы `createElement` и удаляет типы.
3. **MyReact** во время выполнения вызывает компоненты, хранит состояние и обновляет DOM.

Браузер получает JavaScript из `dist/assets`. Наличие `.js` в сборке правильно: миграция касается исходников.

`npm run typecheck` проверяет типы без создания файлов. `npm run build` сначала проверяет типы, затем собирает приложение. Компиляция не проверяет реальный ответ сервера или все действия пользователя.

## 2. Архитектура

```text
index.html                   контейнер #root
src/main.tsx                 запуск приложения
src/app/App.tsx              страницы, сессия, выбор трека
src/app/router.ts            таблица маршрутов
src/app/store.ts             каталог и подписки
src/pages/                   экраны
src/components/layout/       общая рамка страницы
src/components/player/       плеер
src/components/sidebar/      боковая панель
src/components/ui/           небольшие переиспользуемые элементы
src/features/auth/           вход и сессия
src/features/signup/         регистрация и валидация
src/features/music/          каталог и подготовка подписей
src/shared/api/              транспорт и разбор ошибок
src/shared/lib/              роутер и общие функции
src/types/domain.ts          модели данных приложения
src/types/jsx.d.ts           допустимые JSX-теги и свойства
createElement.ts             создание виртуального элемента
render.ts                    согласование с DOM и useState
```

**Страница** объединяет части конкретного экрана. `HomePage` знает о треках и подборках.

**Компонент** отвечает за часть отображения. `FormField` связывает подпись, поле и ошибку, но не решает, на какой сервер отправить регистрацию.

**Feature-модуль** знает предметную операцию: выполнить вход, получить каталог. Он не создаёт HTML.

**Store** хранит общие данные и уведомляет подписчиков. Сам store не вызывает MyReact: подписчик в `mountApp` вызывает `renderCurrent`.

**Движок** ничего не знает о музыке и аккаунтах. Он работает с элементами, props, состоянием и DOM.

Не нужно создавать отдельный файл для каждой строки. Разделяй код там, где действительно появляются разные обязанности.

## 3. Проектируем компонент

Перед написанием ответь:

1. Что компонент отображает?
2. Какие данные получает от родителя?
3. Какие данные принадлежат самому компоненту?
4. О каких действиях сообщает родителю?

Пример для нового файла `src/components/music/TrackCard.tsx`:

```tsx
import { createElement } from '../../../index.ts'
import type { Track } from '../../types/domain.ts'

interface TrackCardProps {
    track: Track
    selected?: boolean
    onSelect: (track: Track) => void
}

export function TrackCard({ track, selected = false, onSelect }: TrackCardProps) {
    return (
        <button
            type="button"
            className={selected ? 'track-card is-active' : 'track-card'}
            onClick={() => onSelect(track)}
        >
            {track.title ?? 'Без названия'}
        </button>
    )
}
```

Это учебный пример: файл и его использование автоматически не добавлялись.

Разбор синтаксиса:

- `import { createElement }` импортирует настоящую функцию. Её использует преобразованный JSX, хотя явного вызова не видно.
- `import type` импортирует описание типа, которое исчезнет из JavaScript.
- `interface` описывает контракт объекта.
- `track: Track` — обязательное поле.
- `selected?: boolean` — необязательное поле, которое может быть `undefined`.
- `(track: Track) => void` — тип функции. Она получает трек, а компонент не использует её результат.
- `{ track, selected = false, onSelect }` — деструктуризация одного объекта, а не три аргумента.
- `: TrackCardProps` относится ко всему объекту аргумента.
- Значение по умолчанию применяется для отсутствующего свойства или `undefined`, но не для `null`.
- `export` позволяет импортировать функцию в другом файле.
- `return (...)` возвращает описание интерфейса, а не DOM-узел.

Тип результата выводится автоматически. Можно написать `: VNode`, но это необязательно.

Не объявляй компонент внутри функции родителя. Тогда на каждом вызове родителя будет создаваться новая функция. Движок сравнивает типы компонентов по ссылке и может пересоздать ветку с потерей состояния.

## 4. Типы, которые используются в приложении

```ts
let user: User | null = null
```

`|` — объединение: пользователь или `null`. Перед обращением к свойствам нужно исключить `null`, например через `if (user)` или `user?.email`.

```ts
interface Catalog {
    tracks: Track[]
    artists: CollectionItem[]
    albums: CollectionItem[]
}
```

`Track[]` — массив объектов Track, а не один трек и не массив любых значений.

```ts
type CatalogStatus = 'idle' | 'loading' | 'ready' | 'error'
```

Это конечный набор допустимых строк. Опечатка `'loadng'` станет ошибкой проверки типов.

```ts
const [likedTracks, setLikedTracks] = useState<Record<string, boolean>>({})
```

`Record<string, boolean>` — словарь: строковый ключ → boolean. `<...>` задаёт параметр типа обобщённой функции. Пустой объект сам по себе не объясняет компилятору, какие поля появятся позже.

```ts
setState(update: Partial<S> | ((state: S) => Partial<S>))
```

Это часть контракта store. `S` — тип его состояния. `Partial<S>` делает поля необязательными: можно передать только изменившиеся.

**Store объединяет частичное обновление со старым объектом. `useState` заменяет значение целиком.** Для локального состояния используй:

```ts
setState(previous => ({ ...previous, pending: true }))
```

`...previous` копирует прежние поля, следующий `pending` перезаписывает одно из них. Копирование поверхностное: вложенные объекты не клонируются автоматически.

`Pick<T, K>` выбирает поля типа, `Required<T>` делает поля обязательными. Так `TrackList` повторно использует части контракта главной страницы.

`as SomeType` — утверждение разработчика, а не проверка данных. `unknown` означает неизвестное значение: сначала его нужно проверить. `any` отключает такую защиту; для миграции приложения он не понадобился.

## 5. JSX без магии

```tsx
<div className="card">{track.title}</div>
```

Строчная `div` означает DOM-тег. `TrackCard` с заглавной буквы означает переменную с компонентом. `{...}` переключает нас в JavaScript-выражение.

```tsx
{
    error ? <p role="alert">{error}</p> : null
}
```

Это тернарный оператор. `null` ничего не отображает, как и `undefined`, `true`, `false`. Но `0` отображается текстом. Поэтому `tracks.length && ...` при пустом массиве может вывести ноль; используй `tracks.length > 0 && ...`.

```tsx
{
    tracks.map(track => <TrackCard key={track.id} track={track} onSelect={onTrackSelect} />)
}
```

`map` создаёт массив виртуальных элементов. `createElement` разворачивает вложенные массивы детей. `key` должен быть стабильным и уникальным среди соседей.

`key` хранится отдельно от props. Если компоненту нужен ID, передай `track` или отдельный `id`; не рассчитывай получить ключ через `props.key`.

```tsx
onClick={() => onSelect(track)}
```

Создаёт функцию для будущего клика. При рендере действие не выполняется.

```tsx
onClick={onSelect(track)}
```

Вызывает функцию немедленно во время рендера и передаёт её результат вместо обработчика. Это другая программа и обычно ошибка.

`children` — содержимое между тегами компонента. В `AppLayout` это текущая страница. Тип `Child` разрешает элементы, строки, числа, пустые значения и массивы детей.

Компонент нашего движка возвращает один VNode или `null`. Поддержки React Fragment и возврата массива напрямую из компонента здесь нет. Используй общий контейнер.

## 6. Создать JSX — ещё не вызвать компонент

```tsx
<TrackCard track={track} onSelect={onTrackSelect} />
```

Концептуально преобразуется в:

```ts
createElement(TrackCard, { track, onSelect: onTrackSelect })
```

Получается объект:

```ts
{
    type: TrackCard,
    key: null,
    props: { track, onSelect: onTrackSelect, children: [] }
}
```

`type` содержит ссылку на функцию. `createElement` её не вызывает. Позже движок назначает компоненту путь, выбирает ячейки состояния и выполняет функцию.

Для `<h1>Главная</h1>` типом будет строка `'h1'`. Текст внутри превратится в VNode типа `TEXT_ELEMENT` с `nodeValue: 'Главная'`.

Не заменяй JSX прямым вызовом `TrackCard(props)` в дереве: он обходит назначение отдельного пути компонента. Особенно опасно это для компонентов с `useState`.

## 7. Первый рендер

```text
index.html → main.tsx → mountApp → router.listen
    → событие route → renderCurrent → дерево VNode
    → render → reconcile → функции компонентов → DOM
    → браузер выполняет layout и paint
```

`main.tsx` получает `#root` и проверяет его наличие. `mountApp` создаёт переменные приложения, подписывается на store и маршрут. `router.listen()` сразу сообщает текущий маршрут, поэтому появляется первоначальный экран.

На главной сначала показывается «Проверяем сессию…». Ответ сессии меняет состояние, при необходимости вызывает перенаправление, затем запускается загрузка каталога. Обновление store вызывает подписчика и `renderCurrent`.

`renderCurrent` выбирает страницу, строит `AppLayout → Page` и вызывает `render`. Тот сохраняет корень и запускает `reconcile`.

Если `element.type` — функция, `reconcile`:

1. Запоминает предыдущие путь и индекс хука.
2. Устанавливает путь текущего компонента.
3. Сбрасывает индекс хука в ноль.
4. Вызывает `element.type(element.props)`.
5. Получает возвращённое дерево.
6. Сравнивает его с предыдущим результатом компонента.
7. Сохраняет результат и восстанавливает контекст.

Если тип — строка, движок создаёт или обновляет HTML-, SVG- или текстовый узел, обрабатывает свойства и детей.

**Новый VNode не означает новый DOM-узел.** Компоненты создают новые описания, а `reconcile` часто сохраняет прежние кнопки, поля и текстовые узлы.

## 8. Состояние на примере счётчика

Пример для `src/components/ui/Counter.tsx`:

```tsx
import { createElement, useState } from '../../../index.ts'

export function Counter() {
    const [count, setCount] = useState(0)

    return (
        <button type="button" onClick={() => setCount(previous => previous + 1)}>
            Нажатий: {count}
        </button>
    )
}
```

Это учебный пример, он не добавлен в интерфейс автоматически.

Первый вызов: `useState(0)` находит путь компонента и ячейку с индексом 0. Если её ещё нет, записывает 0. Возвращает `[0, setter]`.

Деструктуризация массива присваивает имена его элементам. Имена произвольные, порядок важен.

Клик: setter читает последнее значение, вычисляет `previous + 1`, сохраняет 1 и **синхронно вызывает render для всего сохранённого корня**.

Компонент выполняется снова. Ячейка уже содержит 1, аргумент `0` не сбрасывает её. Новое описание содержит текст 1, движок обновляет текстовый DOM-узел.

Старый `count` не меняется: это константа предыдущего вызова. Новый вызов создаёт новые локальные переменные и обработчики.

```ts
setCount(count + 1)
setCount(count + 1)
```

Если захваченный `count` равен 0, оба вызова запишут 1, даже при синхронном рендере нашего движка.

```ts
setCount(previous => previous + 1)
setCount(previous => previous + 1)
```

Каждый updater читает последнее значение: получится 2. Это два синхронных рендера, а не пакет обновлений.

## 9. Правила хуков

В `Player` ячейки следуют порядку:

```text
0 → isPlaying
1 → progress
2 → volume
3 → failedCover
```

Состояние связано с **путём компонента и порядком вызовов**, не с именем переменной.

Условный `if (track) useState(...)` сдвинет номера при изменении условия. Одно значение будет прочитано вместо другого.

Вызывай хуки в начале компонента, без условий и циклов, до условных `return`. Не вызывай их в обработчиках и обычных утилитах.

Не вызывай setter при вычислении JSX: он немедленно запустит новый рендер, который снова вызовет setter. Получится рекурсия.

Здесь `useState(() => initialValue)` не выполняет ленивую инициализацию: функция сохраняется как значение. Нет `useEffect`, `useRef`, `useMemo`, Context и batching React.

## 10. Жизненный цикл

### Mount: первое появление

Движок видит компонент по новому пути, вызывает функцию, создаёт состояния и DOM-поддерево. Отдельного callback «компонент смонтирован» нет.

### Update: обновление

Setter, маршрут, store или явный `renderCurrent` приводят к новому дереву. Если путь и тип компонента сохраняются, его состояния обычно сохраняются, а DOM согласуется с новым результатом.

Вызов компонента и изменение DOM — разные события. Компонент может выполниться, но вернуть те же значения текста и атрибутов. Здесь нет `memo`: обновление корня повторно вызывает компоненты дерева.

### Unmount: удаление

Когда ветка исчезает, `reconcile` удаляет DOM, а `clearPath` удаляет записи DOM, результатов компонентов и хуков для этой ветки и потомков.

При повторном появлении состояние начальное. При замене функции-компонента на том же пути старая ветка также заменяется.

`return null` оставляет сам компонент в дереве и убирает его вывод: собственные хуки сохраняются. Если родитель перестал включать компонент, удаляются и его состояния.

**Внешние ресурсы автоматически не очищаются.** Таймер, подписка на window или запрос не исчезнут из-за удаления DOM. Нужен явный владелец и функция очистки.

`mountApp` возвращает функцию, снимающую подписку store и обработчики роутера для HMR. Она не отменяет уже отправленные запросы и не вызывает `render(null, container)`. Это ограничение реализации, не полноценный React unmount. Для новых асинхронных процессов проектируй отмену через AbortController или проверку актуальности результата.

Setter после удаления пути обычно ничего не делает: ячеек больше нет. Но замыкание содержит путь и индекс, а не уникальный ID экземпляра. Старый callback может обратиться к новому экземпляру на том же пути. Не полагайся на это как на отмену старых запросов.

## 11. Ключи и идентичность

`getChildPath` строит путь по `key`, иначе по индексу. Внутри родителя `0` ключ `track-42` даёт путь `0.key:track-42`.

При перестановке `[A, B] → [B, A]` со стабильными ключами движок находит прежние элементы и переставляет DOM через `insertBefore`. Состояния следуют за ключами.

С индексами идентичность связана с местом: компонент на позиции 0 может получить другой трек и сохранить старое состояние.

Ключ уникален среди соседей, а не во всём приложении. Перенос между разными родителями не сохраняет прежний полный путь.

## 12. События и формы

Используются нативные DOM-события, а не React SyntheticEvent.

```tsx
<input
    type="range"
    onInput={event => {
        const input = event.currentTarget
        if (!(input instanceof HTMLInputElement)) return
        setVolume(Number(input.value))
    }}
/>
```

`target` — исходный элемент события. `currentTarget` — элемент с выполняемым обработчиком. При клике на SVG внутри кнопки это могут быть соответственно `path` и `button`.

TypeScript видит `currentTarget` как `EventTarget | null`. Проверка `instanceof` сужает тип и проверяет реальное значение. После неё доступны `value`, `name`, `form`.

```ts
function submit(event: SubmitEvent) {
    event.preventDefault()
    const form = event.currentTarget
    if (!(form instanceof HTMLFormElement)) return
    const email = getInput(form, 'email').value
}
```

`preventDefault` отменяет обычную отправку браузером. `getInput` проверяет результат `namedItem`: это может быть элемент, список радио-кнопок или null. Прямое чтение `.value` небезопасно.

Перед `await` сохрани DOM-ссылку в локальной переменной. Не рассчитывай получить `event.currentTarget` после завершения обработки события.

`FormField` не принимает `value`: это неконтролируемое поле. Ввод хранится в DOM и читается при отправке. Сохранение узла при рендере помогает не потерять текст. В `Player` диапазон, напротив, получает `value` из состояния.

`form.isConnected` в регистрации защищает от обновления покинутой формы после ответа сервера. Кнопка `disabled` показывает состояние, а `dataset.submitting` защищает от повторного запуска отправки через обработчик.

## 13. Асинхронность и границы типов

Сеть возвращает неизвестные данные. TypeScript не контролирует сервер и не проверяет JSON при выполнении.

```text
requestJson → body: unknown → проверки данных → Catalog → store → props → JSX
```

`getHomeData` проверяет массивы и используемые интерфейсом поля. Произвольный объект вместо названия или исполнителя не должен дойти до JSX.

`readApiError` выделяет строковые сообщения полей. `AuthError` и `SignupError` содержат типизированные ошибки. `errorMessage(error: unknown)` безопасно получает общее сообщение.

`Promise<Catalog>` описывает результат успешного завершения. Ошибку он не описывает: её всё равно нужно обрабатывать.

Не вызывай загрузку непосредственно в теле компонента: оно выполняется при каждом рендере. Здесь загрузка организована в `mountApp` и `appStore.loadCatalog`, где есть защита от одновременно повторяющихся загрузок.

## 14. Три источника обновлений

| Данные         | Где хранятся             | Как запускается рендер               |
| -------------- | ------------------------ | ------------------------------------ |
| Громкость      | useState в Player        | Setter вызывает render корня         |
| Каталог        | appStore                 | Подписчик вызывает renderCurrent     |
| Выбранный трек | activeTrackId в mountApp | onTrackSelect вызывает renderCurrent |

Обычная переменная внутри компонента создаётся при каждом вызове. Переменная внутри `mountApp` сохраняется в замыканиях, потому что `mountApp` не выполняется при каждом рендере. Но её изменение само по себе не обновляет экран.

Props идут вниз, события через callback — вверх. Общий владелец выбранного трека позволяет списку и плееру отображать одно значение.

Текущий Player изменяет UI-состояния. Это не реализация воспроизведения аудио: смена `isPlaying`, `volume`, `progress` сама по себе не создаёт звук.

## 15. Как отлаживать

Поставь точки останова в `createElement`, `render`, функциональной ветке `reconcile`, `useState` и setter. Нажми кнопку плеера.

Перед запуском предскажи:

1. Какая ячейка состояния изменится?
2. Какие компоненты вызовутся снова?
3. Сохранится ли DOM-кнопка?
4. Какие текст, атрибут или иконка изменятся?

`hooksByPath` хранит состояния, `componentOutputByPath` — предыдущие результаты компонентов, `domByPath` — DOM-узлы. Это три разные задачи.

Много вызовов функции компонента не означает много пересозданий DOM.

## 16. Практика с ответами

1. Добавь Counter на страницу и нажми три раза. Получится 3, каждый setter обновит корень синхронно.
2. Дважды вызови `setCount(count + 1)` в одном обработчике. Прибавится 1: оба выражения используют старую константу.
3. Добавь `step?: number` и значение по умолчанию 1. Обновляй через `previous => previous + step`. `step="2"` — ошибка типа, `step={2}` — корректно.
4. Скрой Counter условием родителя и покажи снова. Состояние начальное: предыдущий экземпляр удалён.
5. Переставь два счётчика со стабильными ключами. Состояния следуют за ключами. Без ключей — за позициями.
6. Не передай `onSelect` в TrackCard. TypeScript сообщит об отсутствии обязательного свойства до запуска браузера.
7. Почему `json as Catalog` не защищает от `tracks: null`? Приведение типа исчезает при сборке и не проверяет значения.

## 17. Порядок чтения исходников

1. FormField: контракт, деструктуризация, условный JSX.
2. Player: локальное состояние и события.
3. HomePage: списки, ключи, композиция.
4. SignupPage: формы, валидация, async и ошибки.
5. App: общие данные и жизненный цикл приложения.
6. Store: подписки и частичные обновления.
7. CreateElement: создание описаний без DOM.
8. Render: вызовы компонентов, сравнение, сохранение состояния и DOM.

После каждого файла проговори: «Какие данные входят? Что возвращается? Где состояние? Кто инициирует следующий вызов?». Конкретные ответы превращают JSX из магии в обычный понятный код.
